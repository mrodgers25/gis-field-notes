- [ ] `2026-07` **Failed API calls cached as "not found."** An enrichment script that fills missing attributes on a hosted layer treated "the API call failed" (credits ran out) the same as "searched and found nothing," and cached it. 371 of 418 "not found" results were really failures. The giveaway: real web-search calls took several seconds, but these came back under 1.5 seconds apart in solid blocks. The fix: a distinct error type that never gets cached, a stop after 5 consecutive failures, and a targeted cleanup of the bad cache entries instead of a blanket --force rerun.
- [ ] `2026-07` **Using an LLM with web search to fill gaps in a point layer.** About 150 of ~326 bar and restaurant records were missing a website, Yelp, OpenTable, Instagram or Facebook link. Google Programmable Search had dropped its whole-web option, so I switched to the Claude API's server-side web_search tool. The model searches and also judges whether a result is really that venue, which beat hand-written name and address matching. I kept one cheap guardrail: reject a result whose domain doesn't fit the field, like a Facebook link returned for the Yelp field.
- [ ] `2026-07` **Review before you write to a live layer.** A two-step enrichment workflow: `search` writes a CSV with a confidence score and notes for every field, found or not, and `apply` prints the full pending diff and asks y/N before calling edit_features. A cache keyed by (record, field) makes reruns skip finished work, --limit and --max-queries cap the cost, and a 5-record test run comes before the full batch.
- [ ] `2026-07` **The review CSV that hid earlier results.** Each search run overwrote the review CSV, so values found in earlier runs but not yet applied disappeared from the file I was reviewing, even though they were still in the cache. The fix: always rebuild the CSV from the full cache, plus a free `rebuild` command that regenerates it with no API calls.
- [ ] `2026-07` **Deny-lists beat allow-lists for search eligibility.** I skipped CLOSED records (the domain had both "CLOSED" and "Closed") and non-venue types like Park, Condo and Theater, and only searched OpenTable for restaurants. I used a deny-list of non-restaurant types instead of an allow-list of cuisines, so a cuisine value added to the domain later defaults to eligible instead of being silently skipped. A nail salon in the layer was a reminder that the type list still needs a human look.
- [ ] `2026-07` **Every web map in my account said "Modified: today."** Right after a bulk edit_features run, 154 web maps showed today's Modified date. A read-only diagnostic script showed 152 of them didn't reference the edited layer at all, so the edit couldn't have caused it: editing a layer's attribute data doesn't change a web map's own JSON. The lesson: test the causation before you assume your script broke something.
- [ ] `2026-07` **A 400 error from a smaller model and the web_search tool.** The newer web_search tool version allows programmatic tool calling by default, and Haiku 4.5 rejected the request with a 400 error. Setting `allowed_callers=["direct"]` fixed it. The failed run had already cached its errors as "not found," so that one rerun needed --force.
- [ ] `2026-07` **Prepping federal shortage-area data for ArcGIS Online.** I filtered a dental Health Professional Shortage Area shapefile to one state, kept only Designated records (excluding Proposed for Withdrawal), and kept the geographic and population-group polygons separate from the facility-type records, which ship as a separate point file. The data is in WGS84 with no projected CRS, which is fine for display but needs reprojecting before you calculate areas.
- [ ] `2026-07` **Suppressed small cells are nulls, not zeros.** In a state Medicaid dental utilization dataset, 585 of 3,248 county-by-age rows had a blank rate because small counts are suppressed for privacy. Map them as "suppressed," not 0. The measure text also had trailing-whitespace variants, so I trimmed it before pivoting.
- [ ] `2026-07` **Check field names and join keys before you map.** A health-center sites CSV had two similarly named "Health Center Type" fields: one held FQHC vs. look-alike, the other held admin categories. The shortage-area data used county and state names, while the social vulnerability (SVI) data used tract GEOIDs, so the two couldn't join directly. The SVI table was attributes only and joined to Census TIGER tracts on GEOID.
